# 增量与过滤

过滤规则决定每次从源端读取哪些数据。过滤表达式使用源端数据库语法，最终会拼接到 Reader 的查询条件中。

## 留空即全量

过滤条件留空时，系统按 `1=1` 处理，不会附加任何过滤条件。不需要全量读取时，建议至少配置业务日期条件，避免重复读取历史数据。

## 常用写法

### 按业务日期过滤

```sql
dt='${biz_date_dash}'
```

任务业务日为 2026-01-27 时，实际条件为：

```sql
dt='2026-01-27'
```

适合按日分区、且每次只读取当次业务日数据的源表。

### 字段条件

```sql
status = 1 AND amount >= 100
```

可以组合源表字段和 SQL 条件。字符串和日期值需要按源端数据库语法加引号。

### 增量读取

```text
__max__id
```

平台会从目标端上一业务日期分区读取 `id` 的最大值，再转换为大于条件。例如目标端最大 `id` 为 123456，实际过滤为：

```sql
id > 123456
```

适合单调递增的主键或编号。

## `__max__<field>` 的规则

- `<field>` 是源表字段名，例如 `__max__id`、`__max__order_no`。
- 平台从目标端上一业务日期分区读取该字段的最大值。
- 字段类型必须可比较；如果取不到最大值或类型不兼容，系统会回退为 `1=1` 并记录风险日志。
- 回退后本次会读取全量数据，需要检查目标端数据、字段类型和业务日期分区是否正确。

## 组合示例

业务日期 + 字段条件：

```sql
dt='${biz_date_dash}' AND status = 1
```

业务日期 + 增量：

```sql
dt='${biz_date_dash}' AND __max__id
```

> `__max__<field>` 会自行转换为 `field > max`，不要重复书写比较符号。

## 与动态表名的配合

过滤表达式可以使用与动态表名相同的日期变量，例如：

```sql
dt='${biz_date_dash}'
```

动态表名负责选择源表，过滤条件负责裁剪数据。两者的业务日期来源一致，跨日重试时都跟随任务业务日。

## 注意事项

- 过滤表达式使用源端数据库语法，不同数据库的引号、日期函数和布尔值写法可能不同。
- 字符串和日期值需要显式加引号。
- 不要依赖过滤条件做复杂的业务转换；本平台的目标是 ODS 贴源，不做额外转换层。
- 如果 `__max__` 回退为 `1=1`，本次采集可能重复读取大量数据，应在任务日志中确认风险提示。
- 过滤条件会写入执行快照，历史执行可以追溯当时使用的条件。
