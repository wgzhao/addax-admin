# 调度与并发

## 调度触发

Addax Admin 有两类调度入口：

| 调度器       | 触发方式                              | 处理范围                                    |
| ------------ | ------------------------------------- | ------------------------------------------- |
| 采集源调度   | 每个采集源按 `采集时间` 注册每日 cron | 该源下未设置表级调度时间的采集定义          |
| 表级覆盖调度 | Master 每分钟扫描一次                 | `etl_table.start_at` 非空、命中当前分钟的表 |

采集源 cron 每天触发，但是否真正入队由 `采集日历` 决定。交易日、工作日（含调休）等日历无法用 cron 表达，因此在触发时再判断当天是否属于允许采集的日期。

表级覆盖调度带有约 2 分钟的补偿窗口，用于容忍调度器抖动或短暂重启，避免漏掉某一分钟的触发。

## 业务日期与切日时间

系统配置中的“切日时间”决定任务归属哪个业务日：

- 切日之前启动的任务仍计入上一业务日。
- `biz_*` 日期变量跟随任务业务日。
- `curr_*` 变量使用真实运行时间。

跨日重试或补数时，两者可能不同。配置动态表名和过滤条件前，先确认源表按哪个日期切分。

## 队列与分配

采集任务的核心流程：

1. 调度器把任务写入数据库队列 `etl_job_queue`。
2. Redis 选举出 Master 节点。
3. Worker 通过心跳上报可用 slot。
4. Master 从数据库队列领取任务，通过 Redis pub/sub 推送给指定 Worker。
5. Worker 启动 Addax 子进程执行采集。
6. 执行完成后写回表状态、执行快照、统计和日志。

数据库保存任务和所有权，Redis 负责实时选举、分配和心跳。这样既保留了数据库的持久化和审计能力，又避免所有节点争用数据库队列。

## 所有权租约

每个运行中的队列记录都有一份数据库租约：

- 领取时先获得 60 秒临时租约。
- Worker 确认开始执行后延长到 120 秒。
- 执行期间每 20 秒续租一次。
- 只有租约过期的记录才会被重新分配。
- 如果连续续租失败，Worker 会主动终止本地 Addax 进程，避免旧进程继续写入。

因此，节点崩溃后的恢复时间由租约决定，而不是由任务运行时长决定；长时间任务通过持续续租保持所有权。

## 并发控制

### 节点并发

系统配置中的“节点最大并发”是单节点基础并发，实际值会乘以节点权重：

```text
节点实际并发 = max(1, 节点最大并发 × WEIGHT)
```

- `WEIGHT=1.0`：不缩减
- `WEIGHT=0.5`：承担约一半并发
- `WEIGHT=0.0`：压到最小并发；当前实现至少保留 1 个 slot

多节点部署时，通过不同的 `WEIGHT` 实现加权调度。

### 源级并发

采集源上的“最大并发数”是集群级保证：所有节点该源正在运行的任务总和不会超过该值。即使某个节点还有空余 slot，也不会突破源级上限。

### 队列长度

“采集队列长度”限制等待中的任务数量。排队超过该长度时，新任务会等待下一轮调度。

## 失败与重试

- 任务失败后按指数退避重新入队，初始 30 秒，每次翻倍，最大 1800 秒。
- 采集表上的重试次数决定最多尝试次数。
- 成功执行后重试次数会恢复。
- 可在“采集任务管理”中查看排队中、运行中和最近完成的任务。
- 运行中的任务可以中止；已写入的数据会保留。

## 状态码

| 状态 | 含义           |
| ---- | -------------- |
| `N`  | 未采集         |
| `W`  | 等待采集       |
| `R`  | 正在采集       |
| `Y`  | 已采集         |
| `E`  | 采集错误       |
| `X`  | 不采集（停采） |
| `U`  | 等待更新       |

## 多节点部署

- 每个节点都是 Worker，通过 Redis 心跳上报状态。
- 同一时刻只有一个 Master 负责分配任务。
- Master 故障后由 Redis 选举产生新 Master，调度任务重新注册。
- 每个节点必须使用独立的 `app.home`，不要在两个运行中的 JVM 之间共享同一目录。
- “集群状态”页面显示节点心跳；超过 30 秒未心跳视为离线。

## 手动执行

除了自动调度，还可以：

- 在采集表列表点击「发起采集」。
- 勾选多张表后点击「批量采集」。
- 在采集任务管理中查看执行节点、状态和结果。

手动执行同样经过队列和并发控制，不会绕过源级或节点级上限。
