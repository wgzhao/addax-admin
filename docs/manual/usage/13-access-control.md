# 账号与权限

平台使用「角色 + 采集源授权」两级模型：角色决定账号能做什么，授权决定账号能对哪些采集源做。
采集源是授权边界，采集表、执行、统计、日志和队列都通过 `etl_table.sid` 归属到采集源。

## 角色

| 角色    | 全局读取           | 写操作                                 | 日志与作业内容       | 平台配置                     |
| ------- | ------------------ | -------------------------------------- | -------------------- | ---------------------------- |
| `admin` | 全部               | 全部                                   | 全部                 | 全部                         |
| `user`  | 全部（与 guest 相同） | 仅被授权的采集源                     | 仅被授权的采集源     | 无                           |
| `guest` | 全部               | 无                                     | 无                   | 无                           |

- 读取是全局的：`user` 和 `guest` 都能看到所有采集源、采集表、任务状态和队列，只是不能修改。
  授权只限制写操作和操作型数据，不是读取过滤器。
- `guest` 是登录后的只读角色，不是匿名访问；匿名请求仍然返回 401。
- 目标端、字典、系统配置、告警配置、账号管理、审计和日志清理始终只有 `admin` 可以修改。

## 采集源授权

管理员在「账号管理」中点击 `user` 账号行的「授权」，为每个采集源选择：

- **无**：只读；
- **可操作**（`OPERATE`）：可以编辑采集源、新建/修改/退役/恢复采集表、维护字段映射、
  预览与提交表结构、重新生成作业、执行、补数、终止任务，并查看该采集源日志与作业内容。

规则：

- 只有有效角色为 `user` 的账号可以接受授权；`admin` 已管理全部采集源，`guest` 恒为只读，
  对这两种账号保存授权会返回 400。
- 账号从 `user` 改为 `admin` 或 `guest` 时会清空已有授权，改回 `user` 后需要重新授权。
- 批量操作会校验批次内每一张表；只要有一张表不在调用者的授权范围内，整批拒绝。
- 授权在保存后立即对本节点生效，其他节点最多 30 秒后生效。

## 账号资料

账号记录包含登录名、姓名、邮箱、备注、角色和状态。列表还会显示创建时间、最后登录时间和最近改密
时间：

- 姓名、邮箱和备注在新建或编辑账号时维护；
- `last_login_at` 在成功登录时更新；
- `password_changed_at` 在修改密码时更新；
- 升级前已存在的账号以登录名作为姓名，邮箱和备注为空。

## 登录态失效

JWT 中携带账号的 `auth_version`。角色变更、停用/启用账号和修改密码都会提升该版本，旧令牌在下一次
请求时立即失效，需要重新登录。前端登录后会读取 `/users/me` 的角色和授权，再渲染菜单和操作按钮。

## 敏感数据

- 采集源列表和详情不返回数据库密码。
- 非管理员读取目标端时只保留写入所需的非敏感默认值（`defaultFS`、HDFS 前缀、存储和压缩格式），
  不返回完整连接配置。
- `guest` 看不到采集日志、最后一次错误日志和生成的作业内容。

## 常见问题

**页面没有编辑按钮，或接口返回 403？**
账号角色是 `user` 但没有该采集源的「可操作」授权，或角色是 `guest`。请管理员在账号管理中授权。

**管理员刚授权，为什么其他节点仍然只读？**
授权缓存最长 30 秒，等待后刷新页面即可。

**为什么 `guest` 看不到采集日志？**
这是设计约束：日志和作业内容可能包含连接信息和业务数据，只对被授权的操作者开放。

**能否给普通用户限制到某几个采集源可见？**
当前模型不支持按读取范围过滤。授权只控制写操作，读取对所有登录账号开放。
