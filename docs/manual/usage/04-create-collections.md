# 批量创建采集表

「采集表配置」中的「新增采集表」采用五步流程。一个批次共用一套目标端配置，但每张表会独立返回目标结构、字段映射、告警和阻断原因。

## 五步流程

### 第 1 步：选择采集路由

选择采集源和源库。采集路由由采集源、源库、源表、目标端和目标库共同确定。

同一路由在生命周期内只允许存在一条采集定义。如果表已经退役，应到「已退役」入口恢复，而不是重新新增。

### 第 2 步：选择采集表

从源库中勾选要接入的表。界面会显示已选数量，并区分：

- 可新增的源表
- 已退役、需要恢复的采集表
- 因源停用等原因暂停的采集定义

### 第 3 步：配置目标策略

本批次的配置会应用到所有选中表。

#### 目标配置

| 字段           | 说明                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 目标表结构管理 | `平台创建并维护`（`MANAGED`）或 `目标表已存在，仅校验`（`EXTERNAL`） |
| 目标端         | 从已启用的目标端中选择                                               |
| 目标库名       | 目标端中的数据库/命名空间                                            |
| 目标表名模板   | 支持 `${table}`（源表名）和 `${db}`（源库名），默认 `${table}`       |

界面会实时预览“源表 → 目标库.目标表”，并检查重复目标表名。模板必须保证每张源表映射到唯一目标表；如果多张源表落到同一个目标表，配置阶段会给出告警。

#### Hive/HDFS 目标

| 配置     | 说明                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 分区绑定 | 目标分区键与运行期取值的一对一绑定；一个表最多一个业务日期分区，其余分区键使用固定值 |
| 分区创建 | `平台创建`（`PLATFORM`）或 `外部创建`（`EXTERNAL`）                                  |
| 存储格式 | 为空时沿用系统默认值                                                                 |
| 压缩格式 | 为空时沿用系统默认值                                                                 |

#### 关系型数据库目标

| 配置                     | 说明                                                         |
| ------------------------ | ------------------------------------------------------------ |
| 快照业务日期列           | 可选。配置后目标表增加一个普通快照列，采集时写入当天业务日期 |
| 按源端主键在目标表建主键 | 默认开启；关闭后重复执行的去重交给写入模式或 `preSql`        |

快照业务日期列不是数据库分区字段，也不参与主键。跨天采集时的处理方式见 [目标端能力与表属性](06-target-engines.md#快照式采集)。

### 第 4 步：预览与校验

平台会逐表生成计划，并返回以下状态：

| 状态      | 含义                                                 | 能否提交 |
| --------- | ---------------------------------------------------- | -------- |
| `READY`   | 目标结构、字段映射和契约检查通过                     | 可以     |
| `WARNING` | 存在可安全忽略的额外字段等问题                       | 可以     |
| `ERROR`   | 目标表不存在、类型不兼容、必填字段未映射、结构漂移等 | 不可以   |

每张表可以展开查看：

- 目标表结构
- 源字段与目标字段的映射
- 阻断原因和告警
- 目标 DDL（只读）

阻断表默认不纳入提交。排除阻断表后，可以继续创建其余表。

最终确认前，平台会对纳入创建的表重新执行完整校验，避免预览后目标结构发生变化。如果某张表在预览后发生漂移，该表会被阻断并要求重新预览，其他表仍可独立完成创建。

### 第 5 步：创建结果

提交后逐表返回结果：

- `CREATED`：目标表、字段映射和采集任务初始化完成
- `FAILED`：该表创建失败，界面显示失败原因

失败表不会回滚其他已成功的表。修复原因后可以重新发起。

## 创建完成后

- 新表会出现在「采集表配置」列表中。
- 平台异步刷新源表字段、目标结构和采集任务文件。
- 创建后通常先进入 `U`（等待更新）；异步刷新完成后转为 `N`（未采集）、`W`（等待采集）或其他状态，以界面为准。
- 进入表详情可以查看：
  - **基本详情**：调度、源表、目标表、写入模式等
  - **采集日志**
  - **采集任务配置**：渲染后的 Addax 作业 JSON
  - **字段比较**：字段映射与目标契约
  - **采集结果**
  - **执行快照**
  - **变更历史**

## 批量操作

- **批量采集**：勾选多张表后发起采集。
- **批量修改**：批量调整调度时间、重试次数等配置。
- **批量删除 / 退役**：退役后从日常列表和调度中移除，但保留历史统计、流水和日志。
