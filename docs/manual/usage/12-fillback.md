# 补数回补

补数（也叫补采）用于把“应该采集但没有采集”的历史日期重新采集一遍。正常调度只负责当前业务周期；历史日期用补数处理。

## 入口

打开采集表详情页，切换到「补数」tab。

补数按采集表逐张提交：详情页只处理当前表。需要一次给多张表补数时，仍可在采集表列表勾选多张表后使用「补采数据」弹窗；两者最终都会生成相同的队列任务。

## 选择日期

补数日期从日历中选择，支持：

- **区间**：点选开始日期，再点选结束日期，然后点「添加」。
- **单日**：只点选一天，然后点「添加」。
- **多段不连续区间**：可以分多次添加，例如先加 `01-03 ~ 01-10`，再加单日 `01-13`。
- 已选区间以标签展示，可逐段删除或全部清空；重复日期会自动去重。

日期上限是**系统业务日期**（`BIZ_DATE`，受切日时间影响），不是自然时间的今天：

- 业务日期之后的日期在日历中不可选，后端也会拒绝提交。
- 业务日期通常就是上一个业务日，因此今天及以后的日期一般不可补。

单次提交最多 **20 天**（详情页只选一张表，所以是 20 个日期；列表页多选时是「表数 × 天数」不超过 20）。

## 提交与进度

点击「开始补数」后，每个「表 × 日期」会生成一条独立的队列任务，使用该日期作为任务业务日期。提交是异步的，页面不会等待采集结束。

提交成功后，进度面板每 3 秒刷新一次，直到所有日期进入终态：

| 状态                | 含义                                                        |
| ------------------- | ----------------------------------------------------------- |
| 等待中              | 已入队，等待调度                                            |
| 执行中              | Addax 子进程正在执行                                        |
| 成功                | 该日期采集完成                                              |
| 失败                | Addax 非零退出或执行异常，可展开查看错误                    |
| 已取消              | 被人工终止                                                  |
| 未入队 / 明细已清理 | 提交时已有同表同日期的等待/运行任务，或队列明细已被每日清理 |

批次整体状态包括：排队中、执行中、已完成、部分成功、失败、已取消、明细已清理。

页面会记住最近一次补数批次：刷新页面或重新进入 tab 时会恢复该批次的日期和进度。补数记录只保留「当前/最近批次」，每日队列清理会删除更早的终态明细；执行快照仍可在「执行快照」tab 查询。

## 时间变量

补数只改变本次任务的业务日期，不会修改系统全局业务日期，也不会影响正在运行的其它任务：

- `biz_*` 使用补数选择的日期。
- `curr_*` 使用补数任务真实启动的时间。
- 日期变量通过本次 Addax 子进程的 `-p` 参数传入，全局 `BIZ_DATE` 保持不变。
- 补数任务按目标日期重新生成采集任务内容，不读取「采集任务配置」中手工编辑过的缓存内容。

因此补历史日期时，动态表名、过滤条件、目标分区和快照业务日期列都会按所选日期生成。

## 支持的表

补数需要目标端有「日期维度」：

- HDFS 表：至少有一个 `BIZ_DATE` 类型的分区绑定。
- 关系型目标表：配置了快照业务日期列（`businessDateColumn`）。

以下表不支持补数，提交时会被跳过并记录风险日志：

- HDFS 非分区表。
- 未配置快照业务日期列的关系型目标表。

没有日期维度的表补多个日期会互相覆盖，因此平台直接拒绝，而不是产生重复数据。

## 限制与注意事项

- **同表同日期去重**：如果该表在该日期已经有等待中或运行中的任务（自动调度、手工执行或上一次补数），本次补数会跳过该日期，不会并行执行两条相同任务。
- **全部跳过**：如果本次提交的日期全部被去重，队列里不会留下该批次的行；页面会显示提交结果，但刷新后无法恢复该批次的进度。
- **明细清理**：队列的终态明细会随每日清理删除；超过保留窗口的补数批次不会再出现在补数 tab 中，历史执行结果请查「执行快照」和「采集日志」。
- **手工编辑的任务内容**：补数按系统模板和当前采集定义重新生成，不包含在「采集任务配置」tab 里手工改过的 job。
- **取消**：补数 tab 不提供按批次取消。现有「终止」按采集表生效，会同时停止该表正在运行的自动调度和补数任务，请谨慎使用。
- **补数与自动调度**：补数不会改变采集表的停采/退役状态，也不会修改调度时间。

## 常见问题

**为什么某些日期在日历里点不了？**

日期超过系统业务日期（`BIZ_DATE`）时会被禁用。请先确认「系统配置」里的切日时间和业务日期。

**为什么提交后进度显示“未入队”？**

该日期已经存在等待中或运行中的同表任务，队列按「表 + 业务日期」去重。等原任务结束后再提交即可。

**为什么补数成功但目标没有数据？**

先确认该表是否属于增量采集，且目标端的快照业务日期列、分区绑定是否正确；再检查「采集日志」中的 Addax 输出。没有日期维度的表会被直接跳过。

**补数会修改当前业务日期或影响今天的自动调度吗？**

不会。补数只把目标日期写入本次任务，并重新生成该任务的采集内容；全局业务日期、调度器和其它任务都不受影响。
