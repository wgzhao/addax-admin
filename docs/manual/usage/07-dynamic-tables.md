# 动态表名

动态表名用于处理按日期切分的源表，例如日表、月表。在源表名中写入 `${变量}`，平台会在生成采集任务内容时替换成确定的日期值，并写入任务 JSON。

## 基本语法

```text
t_order_${biz_date_short}
```

如果任务业务日是 2026-01-27，读者实际读取：

```text
t_order_20260127
```

变量使用 `${name}` 形式。源表名字段中出现 `${` 时，平台会执行替换。

> 目标表名模板是另一套占位符，只支持 `${table}`（源表名）和 `${db}`（源库名），不要和日期变量混用。

## 业务日期与生成时刻

| 前缀     | 含义                             | 典型用途                         |
| -------- | -------------------------------- | -------------------------------- |
| `biz_*`  | 跟随任务业务日                   | 日表、月表、按业务日期分区的源表 |
| `curr_*` | 生成任务内容时的真实日期时间     | 快照名称、需要记录生成时刻的场景 |

所有日期变量都在**生成采集任务内容时一次性求值并冻结**，替换结果直接写进任务 JSON，运行时不再解析变量：

- 自动调度的任务在切日刷新（或表定义变更、手工刷新资源）时生成，`curr_*` 取生成任务内容时的真实时间；此后重试沿用已保存的任务内容，日期不会重新计算。
- 补数任务按目标日期重新生成，`curr_*` 取该次生成任务时的真实时间。
- 手工编辑任务内容保存时，按保存时刻冻结。

因此任务配置和执行时写出的 job 文件就是当时实际使用的值，排查问题不需要再推断变量含义。

跨日重试或补数时，业务日期可能不等于生成日期：

- `biz_*` 仍然是任务业务日。
- `curr_*` 是生成任务内容时的真实日期时间。

选择变量前先确认源表是按业务日期还是按生成日期切分。

## 变量目录

### 业务日期

| 变量                 | 含义                     | 格式         | 示例         |
| -------------------- | ------------------------ | ------------ | ------------ |
| `${biz_date_short}`  | 任务业务日期，紧凑格式   | `yyyyMMdd`   | `20260127`   |
| `${biz_date_dash}`   | 任务业务日期，短横线格式 | `yyyy-MM-dd` | `2026-01-27` |
| `${biz_year}`        | 业务年份                 | `yyyy`       | `2026`       |
| `${biz_month}`       | 业务月份，两位数字       | `MM`         | `01`         |
| `${biz_short_month}` | 业务月份，不补零         | `M`          | `1`          |
| `${biz_day}`         | 业务日，两位数字         | `dd`         | `27`         |
| `${biz_short_day}`   | 业务日，不补零           | `d`          | `27`         |
| `${biz_ym}`          | 业务年月                 | `yyyyMM`     | `202601`     |
| `${biz_short_ym}`    | 业务年月，月份不补零     | `yyyyM`      | `20261`      |

### 业务日期时间

| 变量                      | 含义                              | 格式                  | 示例                  |
| ------------------------- | --------------------------------- | --------------------- | --------------------- |
| `${biz_datetime_short}`   | 业务日期与生成时刻的时分秒，紧凑格式    | `yyyyMMddHHmmss`      | `20260127140530`      |
| `${biz_datetime_dash}`    | 业务日期与生成时刻的时分秒，短横线格式  | `yyyy-MM-dd HH:mm:ss` | `2026-01-27 14:05:30` |
| `${biz_datetime_0_dash}`  | 业务日期当天 00:00:00，短横线格式 | `yyyy-MM-dd 00:00:00` | `2026-01-27 00:00:00` |
| `${biz_datetime_0_short}` | 业务日期当天 00:00:00，紧凑格式   | `yyyyMMdd000000`      | `20260127000000`      |

### 生成时刻日期

| 变量                 | 含义                   | 格式         | 示例         |
| -------------------- | ---------------------- | ------------ | ------------ |
| `${curr_date_short}` | 生成时刻日期，紧凑格式   | `yyyyMMdd`   | `20260127`   |
| `${curr_date_dash}`  | 生成时刻日期，短横线格式 | `yyyy-MM-dd` | `2026-01-27` |

### 生成时刻日期时间

| 变量                       | 含义                                | 格式                  | 示例                  |
| -------------------------- | ----------------------------------- | --------------------- | --------------------- |
| `${curr_datetime_short}`   | 生成时刻日期时间，紧凑格式          | `yyyyMMddHHmmss`      | `20260127140530`      |
| `${curr_datetime_dash}`    | 生成时刻日期时间，短横线格式        | `yyyy-MM-dd HH:mm:ss` | `2026-01-27 14:05:30` |
| `${curr_datetime_0_dash}`  | 生成时刻当天 00:00:00，短横线格式   | `yyyy-MM-dd 00:00:00` | `2026-01-27 00:00:00` |
| `${curr_datetime_0_short}` | 生成时刻当天 00:00:00，紧凑格式     | `yyyyMMdd000000`      | `20260127000000`      |

表详情中的“动态命名”帮助弹窗提供同样的变量目录，并支持搜索和复制。

## 示例

### 日表

源表名：

```text
t_order_${biz_date_short}
```

实际读取：

```text
t_order_20260127
```

### 月表

源表名：

```text
t_order_${biz_ym}
```

实际读取：

```text
t_order_202601
```

### 带生成时间戳的快照表

源表名：

```text
t_snapshot_${curr_datetime_short}
```

实际读取：

```text
t_snapshot_20260127140530
```

这是生成该任务内容的时间。生成后表名即固定：自动调度的重试沿用同一个任务内容，不会因为实际启动时间不同而换表；补数会在每次执行前重新生成，表名取该次生成时间。

## 注意事项

- 动态表名只改变读者实际读取的源表，不改变目标表命名。
- 变量名区分大小写，必须与目录一致。
- 如果业务日期或生成时刻不符合预期，先检查系统配置中的“切日时间”，以及任务内容的生成时机（切日刷新、补数执行或手工保存）。
- 跨日重试或补数时，`biz_*` 和 `curr_*` 可能落在不同日期，务必确认源表实际按哪个日期切分。
- 日期变量在生成任务内容时已全部替换为确定值，运行时不再解析 `${...}`；手工编辑任务内容时也按保存时刻冻结。
- 任务配置和执行时写出的 job 文件里保存的都是确定值，排查时直接查看这些字面值即可，不需要再按运行时间推算。
- 动态表名配合过滤条件时，可以在过滤表达式中继续使用同一批日期变量，见 [增量与过滤](08-filtering.md)。
