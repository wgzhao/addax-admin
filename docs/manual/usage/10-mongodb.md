# MongoDB 采集

MongoDB 在本版本中**只作为采集源**，不支持作为目标端。采集到的文档仍写入 HDFS/Hive 或关系型数据库。

## 支持范围

- 一个 MongoDB 采集源可以接入多个数据库：采集源连接配置中的“数据库”只是默认库；新增采集表时还会选择实际源数据库，因此同一个采集源下可以分别接入不同数据库的集合。
- 一张采集表对应一个集合。需要采集多个集合时，分别新增采集表。
- Addax 必须安装 `mongodbreader` 插件。插件缺失时保存采集源会提示，任务运行会失败。
- 管理端内置 MongoDB Java 驱动覆盖 MongoDB 3.6/4.0–7.0（8.0 部分兼容）；实际数据采集由 Addax 的 `mongodbreader` 执行，端到端兼容性以 Addax 端驱动为准。

## 新建 MongoDB 采集源

在「采集源管理」中新增，连接类型选择 `MongoDB`。保存后连接类型不可修改。

| 字段            | 说明                                                                 |
| --------------- | -------------------------------------------------------------------- |
| MongoDB 地址    | 一个或多个 `host:port`，用逗号分隔；不支持 `mongodb+srv://`          |
| 数据库          | 默认数据库；采集表未另行选择源库时使用                               |
| 认证库 authDb   | 账号所在的认证库，常见为 `admin`；界面默认 `admin`                   |
| 高级选项 (JSON) | 可选，例如 `{"tls":"true","replicaSet":"rs0"}`，值使用字符串形式     |
| 用户名 / 密码   | 无认证时都留空；有认证时两者必须同时填写                             |

高级选项支持：

`tls`、`tlsInsecure`、`tlsAllowInvalidCertificates`、`tlsCAFile`、`replicaSet`、`readPreference`、`directConnection`、`retryWrites`、`serverSelectionTimeoutMS`、`connectTimeoutMS`、`socketTimeoutMS`。

其中 `tlsCAFile` 必须是管理端做连接测试以及运行采集的 Addax 主机都能读取到的路径。用户名、密码和 `authSource` 不要写进高级选项，应使用表单字段和认证库。

### 多数据库采集

同一个采集源可以覆盖多个 MongoDB 数据库：

1. 在采集源上配置默认数据库和认证库。
2. 批量新增采集表时，先选择采集源，再选择要采集的源数据库。
3. 为这个数据库下的集合创建采集表。
4. 需要接入另一个数据库时，回到新增采集表流程，选择同一个采集源和另一个源数据库即可。

认证库 `authDb` 是采集源级别的配置，所有数据库共用同一组账号；如果不同数据库需要不同账号，应分别创建采集源。

## 新增采集表时字段从哪里来

MongoDB 集合没有固定 schema。平台的字段契约来自**对集合的采样推断**，不是从源端读取 DDL。

### 采样规则

- 默认最多读取 1000 条文档。
- 集合估算文档数不超过 1000 时，读取集合中的全部文档。
- 文档数超过 1000 时，按 `_id` 升序读取头部、按 `_id` 升序跳过中点读取中部、按 `_id` 降序读取尾部，并按 `_id` 去重。
- 采样结果用于生成源字段、目标字段建议、字段类型和目标 DDL 预览。

### 字段规则

- `_id` 始终是第一列，作为主键且非空。ObjectId 按 24 位字符串处理。
- 嵌套文档展开为点路径，例如 `nested.user.name`；目标列名默认把点替换为双下划线，例如 `nested__user__name`。
- 数组、超过嵌套深度上限的文档，以及文档/标量混合的路径，按 JSON 文本读取；关系型目标映射为 `text`，Hive 目标按类型字典映射（默认 `string`）。
- 同一路径出现多种 BSON 类型时：
  - 全部是数值类型，取范围最宽的类型（`int` → `bigint` → `double` → `decimal`）。
  - 包含字符串或跨类型家族，按 `text` 处理。
  - 全部为 null 时按 `string` 处理。
- 字符串长度取样本中的最大长度，下限 255，关系型目标上限 16383，超过上限时按 `text` 处理；Hive 目标按类型字典映射（默认 `string`）。
- 默认最多 500 个字段、嵌套深度 5；超过限制会截断并给出告警。
- 无法被 `mongodbreader` 寻址的字段（例如带引号的常量、纯数字路径、`*`）会被跳过并给出告警。
- 空集合只能推断出 `_id`，并给出告警；可以在字段比较页手工添加源字段，等数据写入后重新采样。

采样统计（样本数、出现次数、缺失次数、null 次数和 BSON 类型分布）保存在字段元数据中，可在字段比较页的“字段采样信息”中查看。字段注释只记录 BSON 原生类型，例如 `MongoDB objectId`、`MongoDB int32`、`MongoDB mixed`。

### 字段映射与提交

- 源字段名区分大小写，`Code` 和 `code` 可以同时存在。
- 目标列名可以按业务需要在预览阶段修改；平台按大小写不敏感去重，冲突时自动追加 `_2`、`_3` 等后缀。
- 预览展示的是采样快照。提交时平台会重新采样并校验映射；如果预览中出现的字段在提交采样中缺失，该表会创建失败，需要重新预览或手工补字段。
- 平台管理（`MANAGED`）模式下，目标表由平台创建或演进；外部管理（`EXTERNAL`）模式下只校验目标契约，不执行 DDL。

## 切日刷新与表结构

到达切日时间后，Master 节点会逐表刷新源字段和目标结构，并重新生成采集任务模板。MongoDB 采集表和 RDBMS 采集表走同一个刷新入口，但 MongoDB 的“表结构”来自采样：

- 每次刷新都会重新采样集合，更新字段类型、注释和采样统计。
- 采样中新出现的字段会追加到字段列表，并在 `MANAGED` 模式下同步到目标表。
- 类型或注释变化时更新字段契约，并按目标端规则尝试表结构变更；无法执行的变更会记录风险日志，需要人工处理。
- 采样中暂时没有出现的旧字段会**保留原映射，不会自动删除或标记为 `__deleted__`**，同时记录风险日志。这是为了避免稀有字段因采样不到而被误删。
- 表状态正常时，只有采样统计（`source_meta`）变化不会触发目标表 DDL；统计仍会落库。
- 源集合本身不会被修改；平台和 Addax 都只读取集合。
- 源不可达时跳过该表本轮刷新，不会把表标记为采集失败，下一轮会继续尝试。
- `EXTERNAL` 目标只重新校验契约，不执行 DDL。
- 手动执行「更新表结构」与切日刷新使用同一套逻辑。

因此，MongoDB 采集表会随切日刷新字段和目标表结构，但**不会因为采样缺失就删除字段**；这是一种保守的 schema-on-read 策略。

## 过滤与增量

- 过滤条件是 MongoDB 查询文档（extended JSON），不是 SQL。例如：

  ```json
  { "status": "paid", "created_at": { "$gte": { "$date": "2026-11-01T00:00:00+08:00" } } }
  ```

- `__max__<field>` 表示按目标表该字段的最大值做增量，例如 `__max__seq`。
- 包含 `$where`、`$function`、`$accumulator` 的过滤条件会被拒绝。
- MongoDB reader 没有 `splitPk` / `autoPk` 概念，界面不会显示这些选项；字段别名由平台的位置映射保证，不要通过 `reader_plugin_config` 覆盖 `column`，否则会破坏位置对齐。

## 注意事项

- 采样不是完整 schema。只出现在未采样区间、低频写入或未来才出现的字段，可能在当前刷新中看不到；需要时在字段比较页手工添加源字段，或等待下一次刷新。
- 大集合的采样和后端连接检查需要时间。切日刷新是串行执行全部采集表的，单个慢集合可能占用全局刷新超时时间。
- 嵌套文档展开为多个字段；数组整体作为一个 JSON 文本字段，不展开数组元素。
- MongoDB 只支持作为采集源，不能作为目标端。
- `mongodb+srv://` 无法被 Addax `mongodbreader` 表达，必须填写具体的 `host:port` 列表。
- 切换 MongoDB 驱动版本或升级 Addax `mongodbreader` 后，建议先对一张表执行「更新表结构」并检查采集任务 JSON，再批量刷新。
