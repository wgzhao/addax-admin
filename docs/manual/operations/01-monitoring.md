# 执行监控与日志

## 采集任务管理

「采集任务管理」展示排队中、运行中和最近完成的采集任务，包括：

- 执行节点
- 任务状态
- 开始/结束时间
- 关联的采集表
- 运行中的任务可以中止

手动执行或调度入队的任务都会先进入队列，不会绕过并发控制。

## 采集表列表

「采集表配置」按使用中、暂停中、已退役等范围展示采集定义。常见状态：

| 状态 | 含义           |
| ---- | -------------- |
| `N`  | 未采集         |
| `W`  | 等待采集       |
| `R`  | 正在采集       |
| `Y`  | 已采集         |
| `E`  | 采集错误       |
| `X`  | 不采集（停采） |
| `U`  | 等待更新       |

列表行操作包括：

- 发起采集
- 退役
- 恢复（已退役范围）
- 查看详情

批量操作包括批量采集、批量修改和批量退役。

## 采集表详情

详情页包含以下标签：

| 标签         | 内容                                     |
| ------------ | ---------------------------------------- |
| 基本详情     | 调度、源表、目标表、写入模式、重试次数等 |
| 采集日志     | 本次或历史执行日志                       |
| 采集任务配置 | 渲染后的 Addax 作业 JSON                 |
| 字段比较     | 字段映射与目标契约                       |
| 采集结果     | 读写统计和结果                           |
| 执行快照     | 每次执行冻结的配置、字段映射和上下文     |
| 变更历史     | 采集定义的修改记录                       |

### 执行快照

执行快照在采集开始时冻结：

- 采集定义
- 字段映射
- 源表与目标表
- 过滤条件和其他必要上下文

之后修改配置不会改变历史快照。排查“为什么当时读了这些字段/这个表”时，应查看执行快照，而不是当前配置。

### 采集日志

日志来源：

1. 管理界面中的采集日志标签
2. 后端日志目录 `LOG_DIR`（默认 `./logs`，Docker 中默认 `/app/logs`）
3. Addax 程序目录下的 `log/`

如果日志标签为空，先检查任务是否真正启动、Addax 程序目录是否正确，以及日志目录是否可写。

## 监控与告警

「监控与告警」按采集源查看完成情况和异常表。告警通道支持企业微信机器人：

```bash
WECOM_ROBOT_KEY=key1,key2
```

多个 Key 用逗号分隔。未配置时不会发送企业微信告警，但界面内的统计和状态仍然可用。

## 集群状态

「集群状态」展示节点心跳：

- 最近心跳超过 30 秒视为离线。
- 可以查看节点并发、权重和当前运行任务数。
- Master 故障后由 Redis 选举产生新 Master。

## 日志管理

「日志管理」用于查看采集执行日志并按需清理历史记录。清理前确认对应执行快照和统计已经不再需要。

## 建议的运维监控

- 对 `/app/logs` 或 `LOG_DIR` 做日志聚合（ELK、Loki 等）。
- 监控后端端口、数据库连接和 Redis 可用性。
- 监控采集失败率和长时间运行的任务。
- 定期备份 PostgreSQL。
- 多节点部署时监控各节点心跳和权重配置。
