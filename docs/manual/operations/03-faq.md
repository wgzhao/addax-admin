# 常见问题

## 停采、源停用、退役和暂停有什么区别

| 概念             | 影响范围                         | 是否可恢复            | 是否保留历史 |
| ---------------- | -------------------------------- | --------------------- | ------------ |
| 停采             | 当前采集表                       | 可以                  | 是           |
| 源停用           | 该采集源下所有采集定义           | 可以                  | 是           |
| 退役             | 当前采集定义                     | 可以恢复              | 是           |
| 暂停中的采集定义 | 未退役但因停采或源停用不参与调度 | 取决于停采/源停用状态 | 是           |

恢复退役定义不会自动清除表级停采或源停用状态。

## 为什么不能新增某张表

同一采集路由（采集源、源库、源表、目标端、目标库）只允许存在一条采集定义。如果该表之前被退役，路由仍然被占用，应到“已退役”入口恢复，而不是重新新增。

## 为什么目标表没有自动创建

可能原因：

- 目标表结构模式是 `EXTERNAL`，平台只校验，不执行 DDL。
- 目标端方言暂不支持（Oracle、DB2、Sybase、ClickHouse、SQLite）。
- 目标表结构不兼容，预览阶段被阻断。
- 预览后目标结构发生变化，提交时被阻断。

## 字段映射为什么是只读的

字段映射默认只读，避免误改。点击“编辑映射”后才能修改；取消不会保存，保存后会自动重新生成采集任务。

## 为什么修改字段映射后要重新生成任务

Reader 输出别名、Writer 列、目标 DDL、执行快照和错误提示共用同一份映射。保存映射时平台会重新生成采集任务，保证链路一致。

## 为什么不支持 SQL 表达式

平台把目标层当作 ODS 贴源层，只做字段选择和改名，不引入额外转换逻辑，避免把转换风险带进采集链路。复杂转换应在下游数仓完成。

## 为什么会出现重复数据

常见原因：

- 关系型目标没有主键或唯一键。
- 关闭了“按源端主键在目标表建主键”。
- `writeMode` 使用了 `append` 或 MySQL 的 `overwrite`（映射为 `REPLACE INTO`）以外的非幂等语义。
- 跨天采集没有配置 `preSql` 清理当日数据。
- 旧进程未停止时手工重跑任务。

## 为什么补数被跳过

没有日期维度的表补多个日期会互相覆盖：

- HDFS 非分区表
- 未配置业务日期列的关系型目标表

提交补数时会被跳过并记录风险日志。

## `biz_*` 和 `curr_*` 有什么区别

- `biz_*` 跟随任务业务日，受切日时间影响。
- `curr_*` 使用实际运行时间。

跨日重试或补数时两者可能不同。配置前先确认源表按哪个日期切分。

## 动态表名应该怎么写

使用 `${biz_date_short}`、`${biz_ym}` 等变量，例如：

```text
t_order_${biz_date_short}
```

目标表名模板只支持 `${table}` 和 `${db}`，不要混用日期变量。

## 到达采集时间为什么没有触发

依次检查：

1. 采集源是否启用。
2. 采集时间格式是否正确。
3. 采集日历是否允许当天采集。
4. 表级调度时间是否覆盖了源级时间。
5. 表是否停采或已退役。
6. 当前是否有 Master 节点。
7. 节点和源级并发是否已满。

## 任务一直排队怎么办

检查节点并发、源级并发、队列长度、节点心跳和运行中的任务数。必要时在“采集任务管理”中查看排队情况，或调整系统配置中的并发参数；修改节点并发后需要重启所有后端节点。

## 任务卡在运行中怎么办

执行期间 Worker 每 20 秒续租。节点崩溃后要等租约过期才会重新分配。确认旧 Addax 进程已经停止后再手工处理，避免重复写入。

## Addax 程序目录应该填什么

填后端进程可以访问的 Addax 安装目录，例如 `/opt/app/addax`。Docker 部署时必须位于 `app` 容器内，不能指向另一个容器。

## 如何修改 Addax 程序目录

进入「系统配置」修改“Addax 程序目录”并保存。该配置保存在数据库中，不需要改 `.env`。

## 默认密码是多少

默认账号 `admin`，默认密码 `admin123`。首次登录后请立即修改。

## 多节点如何配置权重

每个节点设置不同的 `WEIGHT`（`0.0` - `1.0`），节点实际并发 = 节点最大并发 × `WEIGHT`。所有节点必须连接同一个 Redis 和 PostgreSQL。

## 升级后需要手工迁移吗

从 v4.2.0 升级不需要。服务启动会自动把旧的目标端字段回填到 `target_options`、重建视图并删除旧列。升级前仍建议备份数据库。

## 在哪里查看日志

- 采集日志：采集表详情 → 采集日志
- 后端日志：`LOG_DIR`，默认 `./logs`，Docker 中为 `/app/logs`
- Addax 日志：`<Addax 程序目录>/log/`
- 容器日志：`docker compose logs -f app`

## 如何反馈问题

准备以下信息后提交 Issue：

- 版本号
- 部署方式（Docker/源码）
- 相关日志片段
- 复现步骤
- 是否多节点部署
