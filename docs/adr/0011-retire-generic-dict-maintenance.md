# ADR-0011: 用专用界面取代通用「字典维护」

- 状态：Accepted
- 日期：2026-11-14

## 背景

`sys_dict` / `sys_item` 是系统早期的通用 key/value 配置表。早期系统不完善时，需要临时改动
某些配置，就把这两张表通过「字典维护」菜单直接暴露给管理员：左侧选字典、右侧对明细做裸的
增删改。随着系统成熟，越来越多配置已经有了专门的界面——编号 1000（运行参数）已经在「系统配置」
里维护，作业模板（5000/5001 的一部分）也在同一个页面里编辑。

剩下仍靠裸编辑器维护的字典，其实是被压平成同一张表的几类**语义完全不同的东西**：

| code | 名称 | 语义类别 | 现状 |
| --- | --- | --- | --- |
| 1000 | 系统配置项开关 | 运行参数 | 已在「系统配置」，缺 `SCHEMA_REFRESH_TIMEOUT` |
| 5000 | JOB 模板 | 作业模板（主模板 R2H/R2R） | R2H 已在「系统配置」，R2R 未暴露 |
| 5001 | JOB 模板子模块 | 作业模板（rR/wH/wR） | rR/wH 已在「系统配置」，wR 未暴露 |
| 1021 | 交易日表 | 采集日历 | 只在字典页裸编辑 + 批量生成 |
| 1022 | 工作日历 | 采集日历 | 同上 |
| 2011 | ODS 采集类型映射 | 类型映射参考数据 | 只有裸编辑 |
| 2010 | SQL 保留字 | 静态参考数据 | 启动时并入代码常量，运行期不可变 |
| 1060 | 通用运行状态 | 死数据 | 无任何消费者 |

通用 key/value 编辑器让操作者直接面对"编码 / 键 / 值"这样的存储原语，而不是业务语义，既容易
误改（键名打错、值类型写错、JSON 值非法），也无法承载每类字典真正需要的专属工作流（日历的
批量生成与年度补全、模板的 JSON 校验与占位符、类型映射的源→目标两列）。

## 决策

字典表保留为**存储层**，不再作为**交互层**。每个字典按其语义收敛到"有意义的界面"或"代码常量"：

1. **运行参数（1000）** → 「系统配置」表单，补上 `SCHEMA_REFRESH_TIMEOUT`。
2. **作业模板（5000/5001）** → 「系统配置」的 JSON 模板编辑器，补上 `R2R` 与 `wR` 两个 tab；
   二者保留代码内置默认模板（`DEFAULT_RDBMS2RDBMS_JOB_TEMPLATE` / `DEFAULT_RDBMS_WRITER_TEMPLATE`），
   首次部署时由 `ensureRdbmsTemplates()` 幂等写入，之后开放编辑。
3. **采集日历（1021/1022）** → 新增「采集日历」页，承载覆盖范围告警、按年批量生成、
   交易日年度补全、单日增删（删法定节假日、补调休上班日）。日历数据仍落在 `sys_item`。
4. **类型映射（2011）** → 新增「类型映射」页（源类型 → ODS 类型两列，可增删改）；数据仍落在
   `sys_item`（dict 2011），只换读写端点，零迁移。
5. **静态参考数据（2010/1060）** → 下沉/删除：
   - 2010 SQL 保留字并入 `Constants.SQL_RESERVED_KEYWORDS` 作为唯一真相源，删除启动期的 DB 合并逻辑与种子行。
   - 1060 通用运行状态确认无消费者后，删除种子行与死代码（`dict-store.ts` / `enum-service.ts`）。

通用「字典维护」菜单与通用 `/dicts` 写接口下线，不保留隐藏应急出口：若将来出现"必须直接改字典"
的需求，说明对应管理界面还不够完善，应当继续完善界面，而不是重新打开裸表通道。

## 影响

- **数据零迁移**：日历（1021/1022）与类型映射（2011）继续落在 `sys_item`，只是读写走新的
  类型化端点；`sys_dict` 里 2010/1060 两行与对应 `sys_item` 行在启动迁移中清理。
- **API 收敛**：
  - 保留 `GET/POST /settings/sys-config`、`GET/PUT /settings/job-templates`。
  - 新增 `GET/POST/PUT/DELETE /calendars/*` 与 `GET/POST/PUT/DELETE /type-mappings/*`。
  - 移除 `ParamController` 的通用 dict/item CRUD 与 `RESERVED_DICT_CODES` 保护名单。
- **权限**：新页面维持 `admin` 角色（与字典维护一致），`docs/manual/usage/13-access-control.md`
  中"字典"字样随通用菜单退役同步修正。
- **回滚**：分阶段提交，每个阶段可独立回滚；Phase 3 删除通用端点前，新页面已上线覆盖全部能力。

## 分阶段迁移

- **Phase 1（增量）**：新增「采集日历」「类型映射」页与类型化端点；「系统配置」补
  `SCHEMA_REFRESH_TIMEOUT`、`R2R`、`wR`。此时「字典维护」保留，数据零迁移。
- **Phase 2（切换）**：前端导航移除「字典维护」，新增「采集日历」「类型映射」入口。
- **Phase 3（收口）**：删除 `dict.vue`、通用 `/dicts` 写端点、2010/1060 种子与死代码。
- **Phase 4（文档）**：更新 `docs/manual` 与权限说明。
