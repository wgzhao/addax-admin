# ADR-0018: 采集表筛选面板精简与耗时筛选

- 状态：Accepted
- 日期：2026-11-24
- 关联：ADR-0017（列表高级筛选）、ADR-0012（目标端族/方言建模）、ADR-0008（源级授权只约束写）

> 本文局部修订 ADR-0017 的面板字段集：移除目标族、目标类型、源库类型、表注释四个控件，新增耗时区间。

## 背景

ADR-0017 把目标端拆成「目标族 / 目标类型 / 目标端点」三级、源端拆成「采集源 / 源库类型」两级。实际使用暴露出问题：

1. **三级之间是派生关系，不是独立维度。** `target_type` 由目标端点决定，族又由类型决定；但用户先选族再选类型时，类型列表不会随族收窄，
   看上去像"选了 Doris 族还能选 HDFS 端点"。三个入口要求用户理解一次保存时已被服务端校验过的关系。
2. **采集源决定源库类型。** 一个源只有一种 `db_type`，独立的源库类型筛选只能用于"跨源按类型筛"，对单源排查没有意义，且与采集源选择重复。
3. **表注释筛选与关键字重复。** ADR-0017 第 4 条已把 `tbl_comment` 纳入 `filterColumn`，关键字 `q` 就能覆盖。
4. **时间范围空态不可辨。** 两个原生 date 输入带了 `placeholder`（浏览器忽略它），空值与已选值在当前主题下看起来一样，用户无法确认哪些条件真的生效。
5. **耗时无法按区间筛。** 列表已有「耗时(s)」列和排序，但无法回答"找出超过 10 分钟的表"这类问题。

## 决策

### 1. 目标端只保留「目标端」选择

面板只保留 `targetIds`（目标端多选）、目标库包含、目标端状态；移除目标族 chips 与目标类型多选。

- 目标端已蕴含族与类型（`EtlTargetService` 保存时校验族、类型与模板一致），不需要用户重复表达。
- 采集系统的目标端数量有限，直接列出端点比三级收敛更快。

### 2. 采集源只保留「采集源」

移除 `dbTypes` 筛选。源决定类型，选源即可。

### 3. 移除「表注释」筛选

关键字 `q` 已覆盖 `tbl_comment`（ADR-0017 第 4 条），同一能力保留两个入口只会增加歧义。

### 4. 时间范围空态显式区分

- 去掉无效的 `placeholder="起/止"`。
- 空输入用 muted 色，已填输入用正文色并加粗（`.filter-date--empty` / `.filter-date--filled`）。
- 两个输入加 `clearable`，选中后出现清除按钮；已选条件仍以 chips 呈现。

### 5. 已下线参数保留为 API 表面

`targetTypes`、`dbTypes`、`tblCommentContains` 不再由 UI 发送，但 `GET /api/v1/tables` 继续接受。理由：这些参数已随 ADR-0017 对外发布，
删除是破坏性变更且没有用户收益；需要精简的是"让人困惑的面板"，不是接口。

已知后果：带这些参数的旧深链接不再被前端解析，等价于忽略该条件。

### 6. 新增耗时区间筛选

- 参数：`durationFrom`、`durationTo`，单位秒，闭区间，作用于 `etl_table.duration`（最近一次采集耗时）。
- 负值返回 400，不静默当作"不限"。
- 面板位置：采集行为分组，两个数字输入（最短/最长，后缀"秒"）。
- 与其它条件 AND 组合；chip 显示 `耗时(s) 60 ~ 200 秒`。
- 未采集过的表 `duration = 0`，只会被 `durationTo >= 0` 命中。

## 影响

- **前端**：`TableFilters` 移除 `dbTypes / targetTypes / comment`，新增 `durationFrom / durationTo`；
  `TableFilterPanel.vue`、`filter-fields.ts`、`useTableFilters.ts`、`table-service.ts` 同步；URL 新增两个参数。
- **后端**：`TableListRequest / TableListCriteria / TableSpecifications` 增加耗时区间谓词；`duration` 列已存在，无迁移、无新索引。
- **E2E**：`table-advanced-filter.spec.ts` 改为按目标端 ID 过滤，新增耗时区间、面板精简回归和退役行不计入的断言。
- **权限**：不变（ADR-0008）。

## 未采用

- **保留目标族、让目标类型随族级联。** 仍然是两层表达一个维度，还要维护族→类型映射；直接选端点更短。
- **给采集源标签追加类型文字。** 会改变采集源、工具栏和状态矩阵测试的标签口径，收益低于成本；源列表页已有类型列。
- **给 `duration` 加索引或派生列。** 当前数据量不需要；耗时筛选是低频条件，列表默认按 id 排序。

## 验证

- 目标端深链接与面板选择均能收窄到对应行，chips 可单独移除。
- 耗时区间：`durationFrom=60`、`durationTo=100`、`60..200` 三种组合的行数正确；`scope=ALL` 时退役行按自身耗时命中。
- 面板不再出现目标族 / 目标类型 / 源库类型 / 表注释控件。
- 旧参数（`targetTypes` 等）出现在 URL 中被前端忽略，不产生幽灵筛选。
