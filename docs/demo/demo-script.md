# Addax Admin 5 分钟演示脚本

> 目标：让买方在 5 分钟内看到「健康结论 → 规模价值 → 风险可下钻 → 企业级能力」。
> 使用独立演示库 `addax_admin_showcase`，不要使用生产库或测试回归库。

## 演示前检查

- [ ] 演示库已用 `scripts/demo/seed.sql` 初始化，演示账号可登录。
- [ ] 首页「经营总览」有 12 个采集源（11 个启用）、82 张采集表、365 个业务日。
- [ ] 至少有 2 张失败表、若干缺失表·天、10 张慢表，用于讲风险故事。
- [ ] 通知中心有未读通知；系统状态页节点在线。
- [ ] 浏览器缩放 100%，窗口 1440×900 或更大；使用浅色主题。
- [ ] 关闭无关标签页，避免通知弹窗干扰。

## 0:00–0:30 开场

1. 打开登录页，指出产品名、版本、部署环境与支持入口。
2. 登录后停留在「经营总览」，不要立即滚动。
3. 一句话定位：「这是企业数据采集的控制台，今天的健康度、规模和风险都在首屏。」

## 0:30–1:30 健康结论与规模

1. 指 hero：「今日采集健康度约 90%，70/78 张表完成，2 张失败、3 张进行中。」
2. 指 KPI 行：「今日数据量、完成表数、平均单表耗时、累计数据量；每个数字都有对比和趋势。」
3. 指右侧进度条：「健康、失败、未开始三段的构成，一眼能看出问题占比。」

## 1:30–2:30 今日运行与风险

1. 指「今日运行 · 日切心跳」：「按采集源排成 24 小时时间轴，切日线之后属于上一业务日。」
2. 指「风险与待办」：「失败表、缺失分区、慢表按严重级别排好，点一下就能到表详情。」
3. 点一条失败表状态列的告警图标：
   - 抽屉展示失败阶段、尝试次数、可执行摘要，以及原始日志和执行快照入口；
   - 说明日志过期后失败摘要仍然保留；
   - 进入「采集表详情 → 失败记录」查看历史；
   - 打开「系统管理 → 错误中心」，按阶段/类别筛选，并按错误指纹聚合重复失败。
   - 最后看「执行快照」：冻结了当时的配置，后续改配置不影响历史。

## 2:30–3:30 趋势与价值

1. 返回首页，指「采集量趋势」：「单色面积 + 7 日均线，趋势不会被颜色噪音干扰。」
2. 指「数据源贡献」：「Top 8 + 其他，回答‘数据主要来自哪里’。」
3. 指「规模与价值」：「累计采集量、业务日、源/表覆盖率和健康度，这是给管理层的价值口径。」

## 3:30–4:15 企业级能力

1. 点顶栏铃铛：「最终失败的采集会进入通知中心，标题、失败原因、发生时间都可追踪，点击直达运行日志。」
2. 打开「系统管理 → 系统状态」：「节点、队列、调度与版本一页看清。」
3. 打开「系统管理 → 安全审计」：「登录、配置变更、权限拒绝都有审计记录，可导出 CSV。」

## 4:15–5:00 收尾

1. 点用户菜单 →「系统版本」：「版本、构建、环境、许可与更新日志都在这里。」
2. 指页脚：「文档、系统状态、支持入口；客户交付时可替换为甲方品牌。」（如已启用白标）
3. 收尾话术：「今天看到的是采集链路的经营视图；往下是运行、质量、SLA 三层运维视图，以及审计和状态页。」

## 演示中不要做的事

- 不要打开「系统配置」里的真实路径/连接串，除非已脱敏。
- 不要在生产库执行任何写操作；演示库可重置。
- 不要承诺尚未实现的能力（如告警通道、License 管理）；这些放在后续路线图。
