# 2026-08-05 双节点重启失败根因修复 + v4.1.1 发版评估

## service.sh 重启误杀问题（已修复）

### 现象

两节点集群中，节点 A 重启正常后，节点 B 紧接着重启时有概率失败。日志特征：应用**完整启动成功**（`Started AdminApplication in 30.285s`）后 15ms 内出现 `GracefulShutdown`，全程无任何异常——是外部 SIGTERM，不是启动失败。

### 根因（时间线对齐）

| 时间 | 事件 |
|------|------|
| 09:20:49.7 | 进程启动 |
| 09:21:19.7 | 脚本 30×1s 的 `nc -z` 端口检查超时 → 打印 Failed → `stop()` 发 TERM |
| 09:21:24.2 | Tomcat 才打开 50601（晚于检查窗口 ~4.5s） |
| 09:21:24.5 | 主线程打印 Started 后，shutdown hook 执行优雅关闭 |

本质：**脚本 30s 检查窗口 < 实际启动 ~35s**。双节点同时启动时 DB/Redis 争用让启动更慢 → 概率性跨过 30s 阈值。排除 MasterElectionService（失选只降级不退出）。

### 修复

`scripts/service.sh` 端口检查窗口 30 → 60 秒（约 2 倍余量）。commit `a6b6fcc` `fix(infra): widen service.sh startup wait window`（已提交 master，未推送）。

### actuator 引入评估：不引入

- 根因是检查窗口太短，与检查方式无关，actuator 不改变这一点
- 端口检查已够精确（Tomcat started 到就绪仅差 0.3s；DB/Redis 不可用时端口不会开）
- 项目有 spring-boot-starter-security，引入需额外配置放行 + 暴露面收敛
- 未来若做监控/告警基础设施再评估
