# 前端 AI 友好性改进:保持 Vue + Vuetify,拆分巨型组件并补齐工具链

## 背景与决策

用户提出"是否迁移 React + Next.js 以便 AI 开发"。评估结论:**不迁移**。依据:
- AI 迭代的真实瓶颈是 4 个 750~1200 行的巨型组件、零 ESLint、零单测(仅 96 行 Playwright E2E)、AGENTS.md 失真,与框架无关
- Next.js 对纯静态内网 SPA(nginx 托管、无 SEO/SSR)是负资产;真转 React 也应是 Vite + React SPA
- 迁移成本集中在最难处:23 处 v-data-table slot 定制、312 处主题 CSS 变量、300 行样式覆盖

用户确认方案:保持 Vue 3.5 + Vuetify 4 + Vite 8,做四类改进。分支 `feat/ai-friendly-frontend`(10 个 commit,未提 PR)。

## 关键发现(后续开发必须知道)

1. **Vuetify 4 不再运行时注册组件**:`createVuetify()` 只注册显式传入的 components(默认空),生产靠 vite-plugin-vuetify 编译期 autoImport。测试需显式注册全部组件(`import * as components from 'vuetify/components'`)。
2. **`v-slot:item.xxx` 点号插槽名是 Vue 静态 slot 名的一部分**(Vue 编译器解析为 "item.sourceTable"),vue-eslint-parser 误报为 modifier → `vue/valid-v-slot` 已禁用;`vue/v-slot-style` 的 fixer 安全(只改前缀为 #)。
3. **`vue/v-on-event-hyphenation` 已禁用**:其 fixer 会把 `@update:modelValue` 改成 kebab-case,破坏 v-model 事件契约。
4. **仓库包管理是混合态**:根 package.json 声明 yarn workspaces(无根 yarn.lock),但生产 Dockerfile 只用 frontend/package.json + frontend/yarn.lock(standalone 模式)。在 frontend 跑 yarn 会检测 workspace 根并在根目录生成 lockfile——需临时移开根 package.json 才能 standalone 安装。bun.lock/package-lock.json 并存。后续建议统一包管理器。
5. **unplugin-vue-router 0.19.2 对 route block 自定义 path 的参数不生成类型**(`/table/detail/:tid` 的 params 是 `Record<never, never>`),7 处 `route.params.tid` 已加 cast 修复。该插件已并入 vue-router 5,迁移是后续方向。
6. **master 上 `yarn type-check` 原本就失败**(Dockerfile 用 build-only 跳过),本次已修复为全绿。
7. **vitest 要点**:restoreMocks 只对 spy 生效,vi.mock 工厂的实现在测试间泄漏(用 resetAllMocks);node_modules 需 `server.deps.inline: ['vuetify']` 否则组件内 .css import 撞 Node loader;jsdom 无 matchMedia 需打桩。
