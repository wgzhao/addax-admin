# 2026-07-20 补数(Fillback)采集功能实现

## 背景

由于各种原因（系统停机、数据源不可用等），某些采集源的某些天可能没有采集到数据。需要提供补数功能，让操作员指定采集表和时间范围，系统按正常采集流程重新采集那些天的数据，使用补数日期而非当前业务日期作为采集基准。

## 需求评审决策

| 问题 | 决策 |
|------|------|
| 非分区表多天补数 | 直接跳过，在风险日志中记录 |
| 切日清理冲突 | 人工保证，补采操作在远离切日时间执行 |
| 总量限制 | 表数 × 天数 ≤ 20 |
| 优先级 | 不设特殊优先级，人工保证工作时间隔离 |
| 增量表补数策略 | 用 D-1 作为 lastEtlDate，缺失则回退 1=1 |

## 实现方案

### 核心思路

```
正常采集:  enqueue(biz_date=今天) → 执行时取 etl_job 预生成模板 → addax.sh
补数采集:  enqueue(biz_date=补数日期) → 执行时检测日期不同 → 用补数日期重新生成模板 → addax.sh
```

补数模板在内存中生成，**不持久化到 `etl_job` 表**，避免覆盖正常采集的模板。

### API 设计

```
POST /api/v1/tasks/fillback
{ "tids": [100, 101], "startDate": "2026-07-15", "endDate": "2026-07-18" }
```

### 时间变量处理

`SystemConfigService.getBizDateValuesForDate(targetDate)` 生成与 `getBizDateValues()` 相同的变量集合，但基于目标日期：
- `biz_date_short`, `biz_date_dash`, `biz_year`, `biz_month`, `biz_day`, `biz_ym` 等全部使用补数日期
- `biz_datetime_*` 系列使用补数日期 + 当前时刻
- `curr_*` 系列保持为真实当前时间（执行时间≠业务日期）

三条模板生成链路均正确使用：
1. Reader 模板 (`JobContentService.fillRdbmsReaderJobForDate`)
2. Hive Writer 模板 (`TargetServiceWithHiveImpl.buildWriterJobForDate`)
3. RDBMS Writer 模板 (`RdbmsTargetAdapter.buildWriterJobForDate`)

### 执行时检测

`executeEtlTaskLogic` 比较 `overrideBizDate` 与系统 `bizDate`，不同则调用 `getJobContentForDate` 重新生成模板。

## Bug 修复

### Job/Log 文件名冲突

**问题**：补采时同一张表不同日期的并发任务使用相同的 job 文件和日志文件（文件名只用 targetDb.targetTable + taskId），导致互相覆盖。

**修复**：文件名加入 `bizDateStr`：
- job 文件：`odsq2.cm_user.json` → `odsq2.cm_user_20260716.json`
- 日志文件：`odsq2.cm_user_1780.log` → `odsq2.cm_user_1780_20260716.log`

## 分区创建验证

- `executeEtlTaskLogic` → `targetService.prepareBeforeRun(taskId, tableView, bizDateStr)`
- `bizDateStr` 用补采日期按表 `partFormat` 格式化
- `TargetServiceWithHiveImpl.prepareBeforeRun` → `addPartition` → `ALTER TABLE ... ADD IF NOT EXISTS PARTITION`
