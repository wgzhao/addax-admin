# 2026-07-20 项目理解与代码阅读

## 项目概况

Addax Admin 是为 Addax ETL 引擎打造的企业级数据采集管理与调度平台，Monorepo 结构（backend + frontend）。

- 版本: 4.1.1-SNAPSHOT
- 后端: Java 21 + Spring Boot 3.5.6 + PostgreSQL 16 + Redis
- 前端: Vue 3.5 + TypeScript 5.9 + Vuetify 4.1 + Vite 8 + Pinia 3
- 端口: 前端 3030, 后端 50601

## 核心架构

### 后端
- 分层架构: Controller(14) → Service(20+) → Repository(16 JPA)
- 包结构: `com.wgzhao.addax.admin` 下 15 个子包
- Master/Worker 分布式架构: Redis 选举 Master，Worker 心跳上报，Pub/Sub 分发任务
- 适配器模式: `TargetAdapter` 接口 → Hive 实现 + RDBMS 实现，注册中心动态路由
- 事件驱动: `SourceUpdatedEvent` + `@EventListener` 异步更新任务模板

### 核心组件
1. **TaskQueueManagerV2Impl** (1097行): 分布式任务队列
   - PG LISTEN/NOTIFY 近实时分发 + 3秒轮询兜底
   - 租约续租机制 (7300s lease, 2433s 续租)
   - 指数退避重试 (30s→1800s 封顶)
   - 死 Worker 即时检测与任务释放
   - SWRR 平滑加权轮询负载均衡
   - WorkerLedger 容量账本 (reserve + reconcile)

2. **TargetServiceWithHiveImpl**: Hive 表结构演进
   - 自动建表/加列/改类型
   - URLClassLoader 动态加载 Hive JDBC 驱动
   - 增量采集 (Redis 缓存 max value)

3. **三层调度**: CollectionScheduler(源级) + TableOverrideScheduler(表级,2分钟补偿窗口) + TaskSchedulerService(通用Cron)

### 数据库
- ~20张表 + 1视图(vw_etl_table_with_source) + 触发器(自动变更审计)
- 核心: etl_table ←→ etl_source / etl_target / etl_column / etl_job / etl_job_queue
- 队列优化: 部分索引(pending/running) + 唯一约束防重入 + FOR UPDATE SKIP LOCKED

### 前端
- 文件路由 (unplugin-vue-router): `<route>` 块声明元信息，导航菜单自动生成
- Service 类 + Requests 封装: 每个资源一个 Service 单例，Axios 拦截器处理鉴权/401
- Pinia + 模块级状态混合: notifier 双模式导出(组合式+函数式)
- 默认暗色主题，完整明暗色板，CSS 变量驱动

## 补数(Fillback)功能实现

### 需求
用户指定采集表 + 时间范围，系统对范围内每一天按正常采集流程重新采集，使用补数日期而非当前业务日期。

### 评审决策
1. 非分区表直接跳过，记录风险日志
2. 切日清理由人工保证（补数在远离切日时间执行）
3. 表数 × 天数 ≤ 20
4. 不设优先级（人工保证补数在工作时间，正常采集在非工作时间）
5. 增量表用 D-1 作为 lastEtlDate，缺失则回退 1=1

### 关键约束（代码调研）
- 模板日期"烧入"：Addax JSON 在 `updateJob()` 时固化日期，执行时 `getJobContent()` 不替换
- `overrideBizDate` 已存在于 `executeEtlTaskLogic`，但仅用于分区创建
- 唯一约束 `uniq_active_etl_job` 只对 pending/running 生效，已完成任务不阻止补数
- 增量采集 `__max__` 依赖 `getLastEtlDateByTid`，补数时需用 D-1 替代

### 实现方案
- 补数任务入队时 biz_date 设为补数日期，payload 标记 `action: "fillback"`
- 执行时检测 `overrideBizDate != systemBizDate` → 调用 `getJobContentForDate(tid, date)` 重新生成模板
- `getJobContentForDate` 用目标日期的变量 Map 生成 reader/writer JSON，增量表用 D-1 作为 lastEtlDate
- 模板在内存中生成，不持久化到 etl_job 表

## 补数 Bug 修复：job 文件和日志文件名冲突

### 问题
`executeEtlTaskLogic` 中 job 文件名和日志文件名仅用 `targetDb.targetTable` 和 `taskId`(表ID)，不包含 biz_date。
同一张表的多个补采任务并发执行时，互相覆盖 job 文件，导致所有 addax 进程读到同一个日期的模板，
全部写向同一个 HDFS 分区目录，产生 `File does not exist` / `Failed to move to trash` 错误。

### 修复
在 `TaskQueueManagerV2Impl.executeEtlTaskLogic` 中，job 文件名和日志文件名加入 `bizDateStr`：
- job 文件: `odsq2.cm_user_20260716.json` (原: `odsq2.cm_user.json`)
- 日志文件: `odsq2.cm_user_1780_20260716.log` (原: `odsq2.cm_user_1780.log`)

### 变更文件
- `service/impl/TaskQueueManagerV2Impl.java` — 第 900、907 行修改文件名格式
